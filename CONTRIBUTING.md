# Участие в разработке

Перед изменениями прочитайте [обязательные правила](CLAUDE.md), [команды проекта](AGENTS.md),
[текущий статус](docs/STATUS.md) и [карту архитектуры](docs/ARCHITECTURE.md).

Интерфейс, комментарии и сообщения коммитов — на русском. Код следует стилю соседних модулей.
Изменения отправляются в основную ветку `main` по правилам владельца проекта;
для внешних предложений используйте Pull Request в `main` с описанием результата и проверок.

## Подготовка и проверки

Нужен Python 3.12+. Создайте `.venv`, активируйте его и установите `requirements-dev.txt`.
Точные команды для разработки и выпуска находятся в [AGENTS.md](AGENTS.md).

Перед коммитом выполните:

```text
ruff check app tests scripts
pytest -q
```

На Linux без экрана: `QT_QPA_PLATFORM=offscreen pytest -q`.
Тесты предметной логики используют сохранённые фикстуры, сетевые API не вызываются.
Длительные операции должны поддерживать отмену; пути и сборка проверяются также на Windows.

## Сопровождение изменения

Добавляйте код в слой его ответственности. Новые правила лицензий, дублей и статистики
сопровождаются тестами на фикстурах. Цвета, размеры и шрифты задаются в `app/core/design.py`.
Обновляйте текущий статус и документацию; новые решения пользователя фиксируются в CLAUDE.md с датой.

Секреты и пользовательская папка `Данные` не входят в репозиторий.
Для обсуждения ошибки укажите версию, шаги воспроизведения и результат; файлы с ключами не публикуйте.

Повышение `__version__` запускает отдельный выпуск после успешных проверок.
Обычная правка документации или структуры репозитория версию автоматически не меняет.
Имена ZIP/SHA-256 и правила хранения трёх последних выпусков описаны в AGENTS.md.
