## Коротко о проекте

- Портативная программа для Windows (PyQt6), репозиторий `r4v3r-63/copy-video-finder`, ветка `main`, текущая версия кода — `app/__init__.py` (`__version__`, сейчас 0.26.0; состояние выпуска проверять в GitHub Releases).
- Пользователь один, общается по-русски. Интерфейс, сообщения, комментарии в коде, коммиты — на русском.
- Пользователю нужны только бесплатные варианты (поисковики, API).

## Команды

```
python -m venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
QT_QPA_PLATFORM=offscreen pytest -q                  # на Linux без экрана; сейчас 596 passed, 1 skipped
ruff check app tests scripts
python -m app.main                                   # запуск
```

Перед каждым коммитом — `ruff check app tests scripts` и `pytest`. Workflow «Проверка кода» (`check.yml`) гоняет их на каждый пуш; сборка — на windows-latest, поэтому пути в тестах и коде должны работать и с `\`.

## Выпуск версии

1. Поднять `__version__` в `app/__init__.py`, коммит, пуш в `main`.
2. После успешного задания `check` workflow `check.yml` сравнит версии до и после всего пуша (`scripts/release_version.py`). Только повышение версии на `main` вызывает `build.yml` с точным SHA проверенного коммита. PR, ручная проверка, обычные правки, понижение версии, перезапись истории и уже существующий или более новый тег выпуск не запускают.
3. Дождаться зелёной цепочки в «Проверка кода»: Windows-тесты, сборка, проверка запуска и публикация выполняются автоматически. Дополнительный токен и доступ облачной среды к GitHub API не нужны: используются `GITHUB_TOKEN` и прежние секреты сборки внутри Actions.
4. Workflow сам создаст тег `vX.Y.Z` и выпуск с `CopyVideoFinder-vX.Y.Z-windows.zip` и `.sha256` — имена не менять (на них завязано автообновление). Выпуски одной версии выполняются последовательно; существующий выпуск не перезаписывается. Неудачная сборка тег не создаёт: повторить неуспешные задания CI либо вручную запустить `gh api -X POST repos/r4v3r-63/copy-video-finder/actions/workflows/build.yml/dispatches -f ref=main -f "inputs[version]=X.Y.Z"` (или Actions → «Сборка для Windows» → Run workflow). Для повторения старого коммита использовать перезапуск исходного CI; ручной запуск с `ref=main` собирает текущий `main`.
5. Старые выпуски — workflow `cleanup-releases.yml` вручную (`keep`, `dry_run=false`).

## Секреты — строго

- API-ключи не хранить в коде и не коммитить. Встроенные ключи — только секреты репозитория (`PIXABAY_API_KEY`, `VIMEO_TOKEN`, `COVERR_API_KEY`, `PEXELS_API_KEY`, `EUROPEANA_API_KEY`, `TAVILY_API_KEY`, `BRAVE_API_KEY`); сборка пишет их в `defaults.json`. Тест `test_no_api_keys_in_repository`.
- Токены VK, ключи пользователя — только в «Данные/settings.json» (в `.gitignore`). Пароли пользователя программа не принимает и не хранит.
- В VK ID приложения пользователя (ID 54837826) нельзя записывать в репозиторий защищённый и сервисный ключи — они не нужны (вход PKCE).

## Важные места кода

- Справочник услуг — `resources/processes.json`, версия 5: 20 разделов (`Category`), 87 групп (`Process`), 375 услуг сайта (`variants`; эталон — `tests/fixtures/site_services.txt`, кроме исключённого «Перевода документов»; каждая ровно в одной группе). Файл нормализован через `processes.save_catalog` — править в том же формате. Старые коды → новые: `"migrated"` в JSON, перенос привязок — `Catalog._migrate_links` (метка `meta.directory_version`). Поле `removed` исключает услуги также из старых пользовательских копий; при открытии каталога их привязки снимаются, ролики сохраняются.
- Новые фразы поиска проверять тестом `test_level_phrases_pass_own_topic_filter` (фраза одним широким словом тему не подтверждает).
- Структура: `core/` → `storage/` → `sources/` → `services/` → `export/` → `workers/` → `ui/`, импорты только вниз. Фоновый поток — тонкий `QThread` в `workers/` над синхронной функцией из `services/`; Qt в логике запрещён. Новая площадка подключается в `sources/registry.py`. Главное окно только собирает части: вкладка «Поиск» — `ui/tabs/search_tab.py`, скачивание — `ui/downloads.py`, команды меню — `ui/actions/`, общее состояние — `ui/context.AppContext`; связь — сигналами `message`/`catalog_changed`.
- Площадки — `app/sources/`, общий HTTP-слой с кэшем и лимитами — `sources/http.py`. Wikimedia Commons исключена из поиска (решение пользователя), модуль остаётся.
- Фоновые потоки при закрытии окна отменяются и дожидаются (`closeEvent`); FFmpeg — через Popen с опросом отмены.
- Цвета/размеры — только `app/core/design.py` (тест `test_no_colors_outside_tokens`).
- Согласованное оформление — `docs/mockups/appearance-preview.png`: светлый Fluent и тёмная медиатека. Карточки выдачи рисует `ui/widgets/result_cards.py`, данные по-прежнему в `QListWidgetItem` (важно для фильтров, сортировки и фоновых превью). Сведения плеера сворачиваются, но предупреждение о лицензии остаётся видимым; «В каталог» подтверждает проверку, как и прежде.
- Добавление по ссылке — `app/services/manual.py`, `ui/dialogs/add_link_dialog.py`, кнопка в каталоге. Повторная ссылка открывает прежнюю запись без изменения пользовательских отметок; без ключа известной площадки сохраняется только ссылка, без утверждения о свободной лицензии.
- Ревью 0.24.0 и внешние ограничения — `docs/CODE_REVIEW.md`; подготовленные примечания выпуска — `docs/release-notes/0.24.0.md`. Не путать подготовленную версию с опубликованным выпуском.
- Без прямого видео или после ошибки QMediaPlayer исходная страница автоматически открывается внутри панели; внешний браузер — только по отдельной кнопке. Для скачивания со страницы доступно качество «Авто». Картинки выдачи группируются по полученному URL: один запрос на картинку за поиск, без повторов при отказе; ответ обновляет все ожидающие карточки. Яндекс может прислать описание и картинку разными записями — `sources/yandex_video.py` объединяет их.
- В текущем облачном сеансе `api.github.com` блокируется прокси даже после публикации разрешения домена. Не просить повторно добавлять тот же домен. Git и страницы github.com доступны; 0.24.0 выпущена ручным запуском workflow пользователем, результат и архив проверены. Последующие повышения версии выпускаются внутри Actions автоматически.
- Тесты окон: одно `QApplication` из `tests/conftest.py`; не вызывать `processEvents`/`show` без нужды — роняло полный прогон.

- Проверка горизонтальности — `core/orientation.py`: полезная область без чёрных полей, три кадра, одиночная обложка не подтверждает весь ролик. В покрытие, M3U и шоурил — только проверенное горизонтальное содержимое; старые записи сохраняются непроверенными. Явное подтверждение после просмотра — отдельная галочка в плеере и каталоге.

- Встроенный сайт — `ui/widgets/site_player.py`: Windows WebView2 (`windows_site_view.py`), Linux Qt WebEngine. Реальное воспроизведение проверяет `scripts/check_site_player.py` на локальных H.264/VP8 фикстурах. Переносимый runtime — `scripts/prepare_webview2.ps1`, подпись Microsoft обязательна; нельзя отключать sandbox/проверку TLS, конструировать ссылки на медиафайлы или включать JS-мост к Python.
