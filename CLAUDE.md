# Поиск видео для копицентров Copy.ru

Портативная программа для Windows. Ищет на бесплатных видеостоках короткие ролики о полиграфическом производстве, проверяет лицензию, даёт посмотреть и скачать подходящие и ведёт каталог покрытия по 43 техпроцессам.

Полное ТЗ: https://claude.ai/code/artifact/01bf5451-bb56-4330-8ba7-38faf84738ca

## Главное

Основной функционал — один сценарий: пользователь вводит название услуги (с подсказками из справочника 43 услуг или произвольный текст) → программа подставляет русские и английские поисковые фразы этой услуги и ищет на всех площадках → показывает только ролики с подходящей лицензией → пользователь смотрит и скачивает.

Главный экран — одно поле ввода и результаты. Каталог, статистика, пакетный поиск и экспорт — во второстепенных вкладках и делаются только после того, как основной сценарий полностью работает. Ничто не должно усложнять главный экран.

Поиск всегда идёт на двух языках — русском и английском. У каждой услуги в справочнике есть `phrases_ru` и `phrases_en`. Свободный русский текст ищется как есть и в переводе по словарю `terms_ru_en.json`; свободный английский — как есть, плюс русские фразы услуги, если он совпал с её английской фразой. Внешние сервисы перевода не используются. Запросы строит `app/query.py`.

Поиск — в первую очередь по полиграфическим услугам: свободный текст сначала сопоставляется со справочником (категория, синоним или все слова запроса в названии услуги — до 4 услуг) и ищется по их фразам; перевод по словарю — только если ни одна услуга не подошла. Выдача — только полиграфия и сувенирка: у ролика должно быть слово этой области (`topic.PRINT_DOMAIN`) и не должно быть слов чужих областей — стройка, еда, природа, музыка (`topic.FOREIGN`). Поиск площадок нечёткий, поэтому ролик показывается, только если в названии или тегах есть ВСЕ обязательные слова хотя бы одной фразы поиска (`search.is_relevant`, `topic.phrase_stems`; необязательные слова — `topic.OPTIONAL`; фраза из одного широкого слова (`topic.BROAD`: «этикетки», «календарь», «label»…, сравниваются целые слова) тему не подтверждает, кроме ключевых слов услуги (`SearchQuery.key`); слова-исключения услуги (`exclude` в справочнике, например «3d» у лазерной печати) отсеивают ролик; у Wikimedia — только по названию файла). К фразам добавляются короткие ключевые слова услуги (`key_ru`, `key_en` в справочнике). Отсеянные «не по теме» можно показать кнопкой; отсеянные по лицензии не показываются никогда. Выдача сортируется по `relevance`: совпадения со словами запроса, затем со словами полиграфии из всех 43 услуг.

Порядок работ: этапы 1–4 из раздела 11 ТЗ — минимальная версия с полным основным сценарием; этапы 5–8 — расширения.

## Стек

- Python 3.12+
- PyQt6 (интерфейс), Qt Multimedia (встроенный плеер)
- requests (запросы к API)
- SQLite (каталог и кэш)
- FFmpeg (конвертация WebM → MP4), кладётся в папку программы
- openpyxl (экспорт Excel), Pillow (поиск похожих дублей: свой dHash в `similar.py` вместо imagehash, чтобы не тянуть numpy и scipy)
- pytest (тесты)
- PyInstaller в режиме onedir

## Каталог (этап 5)

- Ролик в каталоге — уникальная пара (площадка, ID); номер в каталоге (`videos.id`) входит в имя скачанного файла: `ID_техпроцесс_площадка_IDролика`.
- Привязки «ролик — услуга» со степенью соответствия: точное / частичное / смежный процесс / только готовая продукция.
- В панели ролика: «В каталог — лицензию проверил» (отметка «выбрано», лицензия подтверждена, привязка к услуге поиска) и «Не подходит» (отметка «отклонено», ролик больше не показывается в поиске — `SearchWorker(hidden=…)`).
- Скачивание добавляет ролик в каталог, но лицензию не подтверждает.
- В покрытие засчитывается (`Catalog.coverage`) только ролик не «отклонено», с лицензией «Разрешено»/«Разрешено с атрибуцией», подтверждённой пользователем, и со степенью не «только готовая продукция».
- Вкладка «Каталог» (`ui/catalog_view.py`): дерево «категория → услуга» с числом роликов и покрытием «N из цели», фильтры, карточка ролика с правкой названия, отметки, подтверждения лицензии, услуг и комментария.

## Покрытие и пакетный поиск (этап 6)

- Цвет покрытия (`catalog.coverage_level`): 0 — нет роликов, 1, 2, 3 — цель услуги выполнена; в дереве каталога и на вкладке «Покрытие».
- Вкладка «Покрытие» (`ui/coverage_view.py`): статистика ТЗ 7.2 (`catalog.statistics`) и таблица услуг.
- Пакетный поиск (`batch.py`): порядок `catalog.batch_order` — без роликов, с одним, остальные с недостатком; услуги с выполненной целью пропускаются. Только находит кандидатов, ничего не скачивает; ответы кэшируются, поэтому «открыть услугу» потом идёт из кэша.
- История поиска: таблица `seen` (когда ролик впервые попал в выдачу) и `searches`; «новых с предыдущего поиска» — `Catalog.new_since_previous_search`; в выдаче впервые найденные помечены «новый» (кроме самого первого поиска).

## Экспорт и импорт (этап 7)

- Меню «Каталог» (`app/export/`): реестр в Excel (лист «Реестр» + лист «Сводка покрытия») и CSV — строка на каждую привязку «ролик — услуга», все поля карточки (`registry.COLUMNS`); CSV — UTF-8 с BOM и «;» для русского Excel.
- Импорт CSV (`registry.import_csv`) — перенос каталога на другой компьютер: дублей нет (пара площадка + ID), отметки, подтверждение, комментарий, привязки берутся из файла, а статус лицензии пересчитывается по таблице лицензий.
- HTML-каталог (`html_catalog.py`) — один файл, данные встроены, без внешних скриптов; фильтры, поиск, выбор, выгрузка выбранного в CSV — в браузере, без интернета (из сети только превью). Отклонённые ролики не выгружаются.
- Сводка покрытия (`summary.py`): цель выполнена, 2–3 точных ролика, где нужен поиск, площадки, что добавлено с прошлой сводки (дата — `meta.last_summary_at`).

## Дополнительно (этап 8)

- Меню «Поиск»: «История поиска» (`Catalog.search_history`, повтор запроса двойным щелчком) и «Словарь перевода» (`ui/tools.py`): правки сохраняются в «Данные/terms_ru_en.json» и действуют вместо встроенного словаря (`query.Dictionary.load`).
- Плейлист M3U (`export/playlist.py`): `.m3u8` в UTF-8, только скачанные и не отклонённые ролики, пути относительно плейлиста (по умолчанию — в папке роликов).
- Проверка ссылок (`maintenance.check_links`): раз в `Settings.link_check_days` дней при запуске (0 — не проверять, дата — `meta.last_link_check_at`) и по команде меню. «Удалён с площадки» — только по `NotFoundError`; сбой сети или лимит ролик не меняет. Удалённый и не скачанный ролик в покрытие не засчитывается.
- Похожие дубли: dHash превью (`videos.phash`), пары с расстоянием до `similar.DUPLICATE_DISTANCE`; в карточке — «похож на № …».
- Зацикливание: после скачивания FFmpeg сравнивает первый и последний кадр (`downloader.loop_hint` → `videos.loop_hint`); решение пользователя — `videos.loop` в карточке.
- Новые столбцы `videos` добавляются в старую базу через `ALTER TABLE` (`catalog._ADDED_COLUMNS`).

## Интерфейс источника

Каждая площадка реализует `Source` из `sources/base.py`:

- `search(query, filters, page, lang) -> list[VideoResult]` — `lang` (`ru`/`en`) передаётся в параметр языка API (Pexels `locale`, Pixabay `lang`)
- `get_details(source_id) -> VideoResult`
- `get_license(result) -> LicenseInfo`

`VideoResult` содержит: площадку, ID на площадке, название, описание, превью, длительность, ширину, высоту, наличие звука, URL страницы, список файлов для скачивания (качество + URL из API), автора и ссылку на автора.

Уникальность ролика определяется парой (площадка, ID на площадке).

Площадка без ключа API (`is_configured() == False`) в поиске пропускается, пользователь видит это как подсказку, а не как ошибку. Pexels с октября 2026 временно не выдаёт новые ключи, поэтому основные площадки — Pixabay и Wikimedia Commons; модуль Pexels остаётся и включается, как только в настройках появится ключ.

Coverr: длительность в ответе — строка; `is_premium` → «Coverr Premium» → «Отклонено»; `is_ai_generated` — пометка в лицензии; страница ролика — `https://coverr.co/videos/<slug>`. Лицензия Coverr License (коммерческое использование без атрибуции; запрещены перепродажа и обучение ИИ); скачивать только по `urls.mp4_download` — так Coverr учитывает скачивания, просматривать по `mp4_preview` (`VideoResult.preview_video`). Площадка ищет только по-английски (`Source.languages`), русские фразы ей не отправляются.

Europeana: ключ (секрет `EUROPEANA_API_KEY`), только открытые лицензии, лицензия — по ссылке в `rights` (`licenses.name_from_url`); в поиске нет длительности. Internet Archive: advancedsearch, только `licenseurl` CC/PD, без `youtube-*` (правило 5); ссылки на файлы не собираются (правило 2) — ролик скачивают на странице; тема — по названию. Предел длительности по умолчанию — 180 с (раньше 45; при загрузке старых настроек 45 поднимается до 180, `SETTINGS_VERSION`).

Vimeo: личный токен с правами public, поиск `filter=CC`, лицензия каждого ролика из поля `license` (NC/ND — «Отклонено»). Ссылки на файлы (`download`) Vimeo отдаёт не для всех роликов; если их нет, кнопка «Скачать» недоступна, а в лицензии пометка «скачайте на странице ролика». Ссылки на файлы Vimeo не конструировать. Проверено вживую: для чужих CC-роликов `download` пуст, CC-ролики обычно длиннее 45 с; лимит бесплатного приложения — 50 запросов в минуту. Тема у Vimeo проверяется только по названию (теги ненадёжны). Ролики без ссылки на файл стоят в конце выдачи с пометкой «скачать на сайте».

## Жёсткие правила

1. Только официальные API. Никакого парсинга HTML-страниц стоков.
2. Никогда не конструировать URL файлов: использовать только ссылки из ответа API или вставленные пользователем.
3. Соблюдать лимиты: Pexels — 200 запросов в час и 20 000 в месяц; Pixabay — около 100 в минуту, ответы кэшировать 24 часа. Лимиты не обходить.
4. Возле результатов Pexels и Pixabay всегда показывать ссылку на площадку.
5. Mixkit и YouTube не подключать.
6. Лицензии с NC и ND, а также Editorial, Personal, Premium и платные — всегда «Отклонено».
7. Нераспознанная лицензия или голое «Royalty Free» — «Требует проверки»; в покрытие не засчитывается.
8. Ролики со степенью «только готовая продукция» в покрытие техпроцесса не засчитываются.
9. Программа ничего не пишет в реестр и системные папки. Все данные, настройки, ключи API, кэш и журнал хранятся в папке «Данные» рядом с exe (в режиме разработки — рядом с main.py).
10. API-ключи не хранить в коде и не коммитить. Встроенные ключи — только через секреты репозитория (`PIXABAY_API_KEY`, `VIMEO_TOKEN`, `COVERR_API_KEY`, `PEXELS_API_KEY`): сборка пишет их в `defaults.json` рядом с exe, программа берёт их через `Settings.key()`, ключ из настроек пользователя главнее. Тест `test_no_api_keys_in_repository` следит, чтобы ключи не попали в код.

Workflow сам создаст тег vX.Y.Z и выпуск в Releases. Тег `v*`, отправленный вручную, работает так же; из облачного сеанса Claude отправка тегов запрещена.

## Git и GitHub

- Новый отдельный репозиторий на GitHub, рабочее название `copy-video-finder` (не репозиторий ARC Raiders).
- На первом этапе: `git init`, создать репозиторий на GitHub под аккаунтом пользователя (`gh repo create`), первый пуш.
- Коммит после каждого значимого шага, понятные сообщения на русском; пуш на GitHub.
- В `.gitignore`: папка «Данные», ключи API, кэш, скачанные ролики, `.venv/`, `build/`, `dist/`, `__pycache__/`.

## Сборка и поставка

- Автообновление: при запуске программа смотрит `releases/latest` (репозиторий публичный, ключ не нужен) и предлагает обновиться. ZIP скачивается в «Данные/update», сверяется с `.sha256` из выпуска, распаковывается; `update.cmd` ждёт выхода программы, копирует файлы `robocopy /E` (без удаления) и запускает её снова. «Данные» не трогаются. Поэтому имя ассета `CopyVideoFinder-vX.Y.Z-windows.zip` и файл `.sha256` рядом менять нельзя.

- Только PyInstaller onedir. Однофайловый exe не делать: Касперский принимает его за троян.
- FFmpeg и все зависимости — внутри папки сборки.
- GitHub Actions на windows-latest собирает ZIP и публикует его в Releases.

## Как работать

- Разработка идёт по этапам из раздела 11 ТЗ. Каждый этап заканчивается программой, которая запускается и проверяется.
- Новая логика лицензий, дублей и статистики сопровождается тестами на фикстурах из tests/fixtures, без обращений к сети.
- Интерфейс и сообщения пользователю — на русском языке.
