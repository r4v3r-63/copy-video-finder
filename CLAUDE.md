# Поиск видео для копицентров Copy.ru

Портативная программа для Windows. Ищет на бесплатных видеостоках короткие ролики о полиграфическом производстве, проверяет лицензию, даёт посмотреть и скачать подходящие и ведёт каталог покрытия по услугам сайта Copy.ru.

Полное ТЗ: https://claude.ai/code/artifact/01bf5451-bb56-4330-8ba7-38faf84738ca

## Главное

Основной функционал — один сценарий: пользователь вводит название услуги (с подсказками из справочника услуг сайта или произвольный текст) → программа подставляет русские и английские поисковые фразы этой услуги и ищет на всех площадках → показывает ролики по теме с указанием лицензии → пользователь смотрит и скачивает.

Интерфейс — три раздела (решение пользователя 20.10.2026: «упростим программу»): вкладки «Поиск» (строка поиска и результаты; под строкой — одна строка сведений, подробности плана — во всплывающей подсказке), «Пакетный поиск» (одна кнопка — поиск по всем услугам, таблица «найдено / в каталоге») и «Каталог» (сохранённые ролики). Меню — только «Файл» (Настройки, Справочник услуг, Экспорт каталога ▸, Импорт, Сервис ▸ — история, словарь, проверка ссылок, дубли, кэш) и «Справка». Ничто не должно усложнять главный экран.

Поиск всегда идёт на двух языках — русском и английском. У каждой услуги в справочнике есть `phrases_ru` и `phrases_en`. Свободный русский текст ищется как есть и в переводе по словарю `terms_ru_en.json`; свободный английский — как есть, плюс русские фразы услуги, если он совпал с её английской фразой. Внешние сервисы перевода не используются. Запросы строит `app/query.py`.

Поиск — в первую очередь по полиграфическим услугам: свободный текст сначала сопоставляется со справочником (категория, синоним или все слова запроса в названии услуги — до 4 услуг) и ищется по их фразам; перевод по словарю — только если ни одна услуга не подошла. Выдача — только полиграфия и сувенирка: у ролика должно быть слово этой области (`topic.PRINT_DOMAIN`) и не должно быть слов чужих областей — стройка, еда, природа, музыка (`topic.FOREIGN`). Поиск площадок нечёткий, поэтому ролик показывается, только если в названии или тегах есть ВСЕ обязательные слова хотя бы одной фразы поиска (`search.is_relevant`, `topic.phrase_stems`; необязательные слова — `topic.OPTIONAL`; фраза из одного широкого слова (`topic.BROAD`: «этикетки», «календарь», «label»…, сравниваются целые слова) тему не подтверждает, кроме ключевых слов услуги (`SearchQuery.key`); слова-исключения услуги (`exclude` в справочнике, например «3d» у лазерной печати) отсеивают ролик; у Wikimedia — только по названию файла). К фразам добавляются короткие ключевые слова услуги (`key_ru`, `key_en` в справочнике). Отсеянные «не по теме» можно показать кнопкой. Лицензия не отсеивает (решение пользователя 20.10.2026: «ищи любые подходящие ролики»): в выдаче все ролики по теме, свободные (`search.is_free`) выше (`NOT_FREE_PENALTY`), у остальных на плитке «без свободной лицензии», в панели — предупреждение; их можно смотреть, скачивать и добавлять в каталог, но в покрытие они не засчитываются. Не показываются только платные и редакционные (`licenses.is_paid`) и при настройке «только без атрибуции» — всё, кроме «Разрешено». Кнопка «Без свободной лицензии» осталась в коде (`unlicensed_results`), но теперь пуста. Выдача сортируется по `relevance`: совпадения со словами запроса, затем со словами полиграфии из всех групп услуг.

Порядок работ: этапы 1–4 из раздела 11 ТЗ — минимальная версия с полным основным сценарием; этапы 5–8 — расширения.

## Стек

- Python 3.12+
- PyQt6 (интерфейс), Qt Multimedia (встроенный плеер)
- requests (запросы к API)
- SQLite (каталог и кэш)
- FFmpeg (конвертация WebM → MP4), кладётся в папку программы
- openpyxl (экспорт Excel), Pillow (поиск похожих дублей: свой dHash в `similar.py` вместо imagehash, чтобы не тянуть numpy и scipy)
- pytest (тесты), ruff (стиль, `ruff.toml`; workflow «Проверка кода» — ruff и тесты на каждый пуш)
- PyInstaller в режиме onedir

## Справочник услуг (версия 5)

- Решение пользователя 20.10.2026: исключить «Перевод документов» из списка услуг. В 0.24.1 удалена группа `translation`, осталось 375 услуг в 87 группах. Поле `removed` встроенного справочника исключает группу и при загрузке старой пользовательской копии, сохраняя остальные правки. Старые привязки к этой услуге снимаются при открытии каталога; ролики, отметки, комментарии и другие привязки остаются. Снимок исходного списка сайта в тестовой фикстуре сохранён полностью, исключение явно учитывается тестом.
- По решению пользователя 20.10.2026 справочник — услуги сайта Copy.ru (375 после исключения «Перевода документов»; `tests/fixtures/site_services.txt` — исходный список сайта с этим исключением), а не 43 техпроцесса. `Category` — раздел сайта, `Process` — **группа** похожих услуг (ищем, привязываем ролики и считаем покрытие по группе), `Process.variants` — услуги сайта дословно (каждая ровно в одной группе — тест `test_catalog_groups_cover_all_site_services`). Пакетный поиск — по группам (87), не по 375 услугам: иначе не хватит лимитов, а ролики у вариантов одинаковые.
- Коды старых техпроцессов переиспользованы там, где группа им соответствует (`lam_pouch`, `guillotine`, `photo_id`…), их фразы и уровни сохранены; убранные коды → группы в `processes.json["migrated"]`, привязки каталога переносит `Catalog._migrate_links` один раз (`meta.directory_version`), при совпадении — более точная степень. Пользовательская копия справочника версии < 5 откладывается в «Данные/processes.vN.json».
- Подсказки строки поиска — `processes.suggestion_texts`: группы и услуги сайта («Визитки с фольгой (Визитки)»); выбор услуги (`find_variant`) → план группы плюс название услуги по-русски (`query._clean`) и его перевод по словарю, если в нём от двух слов. В словаре `terms_ru_en.json` — слова названий услуг (одежда, материалы гравировки, виды печати).
- `Process.allow` — основы слов из `topic.FOREIGN`, которые для группы свои («дерев» у гравировки по дереву, «медицин» у фото на медкнижку, «электроник» у тампопечати): `in_print_domain(..., allow)` через `SearchPlan.allow`.
- Справочник генерируется скриптом вне репозитория из списка услуг; правки — редактором справочника (поле «Услуги на сайте») или прямо в `processes.json` в формате `save_catalog`.

## Каталог (этап 5)

- Решение пользователя 20.10.2026: завершить оставшиеся пункты ТЗ, выпустить общую 0.24.0, затем провести полное ревью и исправления. В каталоге множественный выбор (Ctrl/Shift), меню «Выбранные» — отметить, отклонить, снять отметку, скачать, скопировать ссылки, проверить ссылки. Массовая отметка не подтверждает лицензию; скачивание из каталога не меняет прежнюю отметку и привязки, выбирает файл по настройке качества и не ставит заново уже активное задание. Проверка выбранных не переносит дату плановой проверки всего каталога. Панель «Фильтры…» — площадка, лицензия, соответствие, скачанные файлы на диске и дата добавления; условия сочетаются.
- Решение пользователя 20.10.2026: добавить ручное сохранение ролика по ссылке. Во вкладке «Каталог» — «Добавить по ссылке…» (`manual.py`, `ui/add_link_dialog.py`): получить сведения в фоне, выбрать группу и соответствие, проверить лицензию на сайте; подтверждение по умолчанию снято. Известные площадки — через существующие API и кэш, YouTube — oEmbed (без скачивания), остальные страницы — VideoObject/Open Graph. Если ключ известной площадки не задан, можно сохранить ссылку с ручным названием и статусом «Требует проверки»; свободная лицензия не предполагается. VK-ссылки `vkvideo.ru` приводятся к ID `vk.com`, как в поиске. Повторная ссылка открывает существующую запись, не меняя её название, отметки, подтверждение, привязки и комментарий. Известные вертикальные/квадратные, платные и редакционные ролики не добавляются. URL файлов не конструируются; отмена запроса не добавляет запись, выход дожидается потока.
- Ролик в каталоге — уникальная пара (площадка, ID); номер в каталоге (`videos.id`) входит в имя скачанного файла: `ID_техпроцесс_площадка_IDролика`.
- Привязки «ролик — услуга» со степенью соответствия: точное / частичное / смежный процесс / только готовая продукция.
- В панели ролика: «В каталог — лицензию проверил» (отметка «выбрано», лицензия подтверждена, привязка к услуге поиска) и «Не подходит» (отметка «отклонено», ролик больше не показывается в поиске — `SearchWorker(hidden=…)`).
- Скачивание добавляет ролик в каталог, но лицензию не подтверждает.
- Путь скачанного файла внутри папки программы хранится относительным (`paths.portable_path` / `resolve_path`, старые абсолютные переводятся при открытии каталога): папку можно перенести или запустить с флешки под другой буквой. Удалённый с площадки ролик засчитывается, только если файл на месте (`Entry.has_file`).
- Повторное скачивание: в файле лицензии — строка «Вариант файла» (качество, обрезка, звук, `downloader.variant`); другой вариант скачивается заново и заменяет файл. Докачка — только той же ссылки и с If-Range: рядом с .part — `.part.json` со ссылкой и ETag/Last-Modified первого ответа; другая ссылка (другое качество), нет валидатора или старый `.part.etag` — .part удаляется; 416 принимается, только если размер из Content-Range совпал. Файлы до 0.18 без строки варианта считаются тем же файлом, только если оба без подготовки к показу и качество совпало.
- Удаление услуги в справочнике снимает её привязки (`Catalog.drop_links`); коды с роликами в каталоге новой услуге не выдаются.
- В покрытие засчитывается (`Catalog.coverage`) только ролик не «отклонено», с лицензией «Разрешено»/«Разрешено с атрибуцией», подтверждённой пользователем, и со степенью не «только готовая продукция».
- Вкладка «Каталог» (`ui/catalog_view.py`): дерево «категория → услуга» с числом роликов и покрытием «N из цели», фильтры, карточка ролика с правкой названия, отметки, подтверждения лицензии, услуг и комментария.

## Покрытие и пакетный поиск (этап 6)

- Цвет покрытия (`catalog.coverage_level`): 0 — нет роликов, 1, 2, 3 — цель услуги выполнена; в дереве каталога и в таблице пакетного поиска.
- Вкладка «Пакетный поиск» (`ui/batch_view.BatchView`): кнопка «Искать по всем услугам» (все услуги, сначала с недостатком роликов — `catalog.batch_order`, затем остальные), таблица «Категория / Услуга / Найдено / В каталоге», двойной щелчок — ролики услуги на вкладке «Поиск». Статистика ТЗ 7.2 (`catalog.statistics`) — в отчёте PDF и сводке, на экране не показывается.
- Пакетный поиск (`batch.py`): порядок — `catalog.batch_order` (без роликов, с одним, остальные с недостатком), затем услуги с выполненной целью. Поминутные лимиты пережидает (`HttpSource.max_wait` = `batch.MAX_WAIT`, запрос уходит только после ожидания), часовые — нет; паузу до `http.SHORT_WAIT` секунд (лимит «1 в секунду») ждёт и обычный поиск; одинаковые сообщения о лимитах показываются один раз. Только находит кандидатов, ничего не скачивает; ответы кэшируются, поэтому «открыть услугу» потом идёт из кэша.
- История поиска: таблица `seen` (когда ролик впервые попал в выдачу) и `searches`; «новых с предыдущего поиска» — `Catalog.new_since_previous_search`; в выдаче впервые найденные помечены «новый» (кроме самого первого поиска).

## Экспорт и импорт (этап 7)

- Меню «Каталог» (`app/export/`): реестр в Excel (лист «Реестр» + лист «Сводка покрытия») и CSV — строка на каждую привязку «ролик — услуга», все поля карточки (`registry.COLUMNS`); CSV — UTF-8 с BOM и «;» для русского Excel.
- Внешние строки — не формулы: в XLSX ячейка с «=» пишется как текст, в CSV перед «= + - @» — апостроф (при импорте снимается); так же — в выгрузке CSV из HTML-каталога (тест через node).
- Импорт CSV (`registry.import_csv`): разделитель — по строке заголовков, без столбцов «Площадка»/«ID на площадке» — ошибка; столбец есть — значение берётся даже «нет»/пустое.
- Импорт CSV (`registry.import_csv`) — перенос каталога на другой компьютер: дублей нет (пара площадка + ID), отметки, подтверждение, комментарий, привязки берутся из файла, а статус лицензии пересчитывается по таблице лицензий.
- HTML-каталог (`html_catalog.py`) — один файл, данные встроены, без внешних скриптов; фильтры, поиск, выбор, выгрузка выбранного в CSV — в браузере, без интернета (из сети только превью). Отклонённые ролики не выгружаются.
- Сводка покрытия (`summary.py`): цель выполнена, 2–3 точных ролика, где нужен поиск, площадки, что добавлено с прошлой сводки (дата — `meta.last_summary_at`).

Удалённый и не скачанный ролик в покрытие не засчитывается.

Блок услуги не разрывается между страницами (`keep_blocks_together`: верхний отступ, не PageBreak — с ним Qt теряет конец документа; после правки — `_relayout`).
- Шоурил (`export/showreel.py`, `ui/showreel_dialog.py`, меню «Каталог»): скачанные ролики услуг (не отклонённые, лицензия свободная и подтверждена — `showreel.suitable`) → один MP4 FFmpeg: по N секунд (короче `MIN_CLIP` — пропуск), 1920×1080 с полями, затемнение, без звука; рядом .txt с авторами и лицензиями (`credits_text`). Превью отчёта — JPEG 16:9 через Pillow (`report.thumb_jpeg`: Qt не читает AVIF Coverr).
- Подготовка к показу: `Settings.trim_seconds` (0 — не обрезать) и `Settings.mute_audio`; при скачивании FFmpeg перекодирует в MP4 с `-t`/`-an` (`DownloadJob.trim/mute`), в файле лицензии — пометка, что ролик изменён.
- Новые столбцы `videos` добавляются в старую базу через `ALTER TABLE` (`catalog._ADDED_COLUMNS`).

## Интерфейс источника

Каждая площадка реализует `Source` из `sources/base.py`:

- `search(query, filters, page, lang) -> list[VideoResult]` — `lang` (`ru`/`en`/`de`/`fr`) передаётся в параметр языка API (Pexels `locale`, Pixabay `lang`); на каких языках площадка ищет — `Source.languages`
- `get_details(source_id) -> VideoResult`
- `get_license(result) -> LicenseInfo`

`VideoResult` содержит: площадку, ID на площадке, название, описание, превью, длительность, ширину, высоту, наличие звука, URL страницы, список файлов для скачивания (качество + URL из API), автора и ссылку на автора.

Уникальность ролика определяется парой (площадка, ID на площадке).

Площадка без ключа API (`is_configured() == False`) в поиске пропускается, пользователь видит это как подсказку, а не как ошибку. Pexels с октября 2026 временно не выдаёт новые ключи; модуль остаётся и включается, как только в настройках появится ключ. Wikimedia Commons исключена решением пользователя; действующие источники перечислены в `docs/STATUS.md`.

Coverr: длительность в ответе — строка; `is_premium` → «Coverr Premium» → «Отклонено»; `is_ai_generated` — пометка в лицензии; страница ролика — `https://coverr.co/videos/<slug>`. Лицензия Coverr License (коммерческое использование без атрибуции; запрещены перепродажа и обучение ИИ); скачивать только по `urls.mp4_download` — так Coverr учитывает скачивания, просматривать по `mp4_preview` (`VideoResult.preview_video`). Площадка ищет только по-английски (`Source.languages`), русские фразы ей не отправляются.

Europeana: ключ (секрет `EUROPEANA_API_KEY`), только открытые лицензии, лицензия — по ссылке в `rights` (`licenses.name_from_url`); в поиске нет длительности. Internet Archive: advancedsearch, только `licenseurl` CC/PD, без `youtube-*` (правило 5); ссылки на файлы не собираются (правило 2) — ролик скачивают на странице; тема — по названию. Только горизонтальные ролики (`SearchFilters.orientation = "landscape"`: ширина больше высоты; вертикальные и квадратные отсеиваются). Предел длительности по умолчанию — 180 с (раньше 45; при загрузке старых настроек 45 поднимается до 180, `SETTINGS_VERSION`).

Vimeo: личный токен с правами public, поиск `filter=CC`, лицензия каждого ролика из поля `license` (NC/ND — «Отклонено»). Ссылки на файлы (`download`) Vimeo отдаёт не для всех роликов; если их нет, кнопка «Скачать» недоступна, а в лицензии пометка «скачайте на странице ролика». Ссылки на файлы Vimeo не конструировать. Проверено вживую: для чужих CC-роликов `download` пуст, CC-ролики обычно длиннее 45 с; лимит бесплатного приложения — 50 запросов в минуту. Тема у Vimeo проверяется только по названию (теги ненадёжны). Ролики без ссылки на файл стоят в конце выдачи с пометкой «скачать на сайте».

## Жёсткие правила

1. В первую очередь — официальные API площадок. По решению пользователя (19.10.2026, 20.10.2026 — обычный поиск по всему интернету, а не только по бесплатным стокам) разрешены также поиск по интернету (`sources/web.py`: поисковики по очереди: Tavily по бесплатному ключу, Brave по ключу, без ключа — DuckDuckGo) и чтение страниц сайтов без API (`sources/videezy.py`, любые страницы с роликом и открытой лицензией в разметке). Страницы читать бережно: свои лимиты, кэш 24 ч, блокировку поисковика не обходить.
2. Никогда не конструировать URL файлов: только ссылки из ответа API, со страницы ролика (Videezy — из кнопки скачивания в сессии сайта, `resolve_download`) или вставленные пользователем.
3. Соблюдать лимиты: Pexels — 200 запросов в час и 20 000 в месяц; Pixabay — около 100 в минуту, ответы кэшировать 24 часа. Лимиты не обходить.
4. Возле результатов Pexels и Pixabay всегда показывать ссылку на площадку.
5. ~~Mixkit и YouTube не подключать.~~ Снято решением пользователя 20.10.2026: YouTube — по oEmbed (название, автор, превью), только смотреть на сайте, файлы не скачиваются; Mixkit — как любой сайт.
6. Лицензии с NC и ND, а также Editorial, Personal, Premium и платные — всегда «Отклонено» (статус лицензии; платные не показываются, остальные «Отклонено» показываются с пометкой и в покрытие не идут).
7. Нераспознанная лицензия или голое «Royalty Free» — «Требует проверки»; в покрытие не засчитывается.
8. Ролики со степенью «только готовая продукция» в покрытие техпроцесса не засчитываются.
9. Программа ничего не пишет в реестр и системные папки. Все данные, настройки, ключи API, кэш и журнал хранятся в папке «Данные» рядом с exe (в режиме разработки — рядом с main.py).
10. API-ключи не хранить в коде и не коммитить. Встроенные ключи — только через секреты репозитория (`PIXABAY_API_KEY`, `VIMEO_TOKEN`, `COVERR_API_KEY`, `PEXELS_API_KEY`, `EUROPEANA_API_KEY`, `TAVILY_API_KEY`, `BRAVE_API_KEY`): сборка пишет их в `defaults.json` рядом с exe, программа берёт их через `Settings.key()`, ключ из настроек пользователя главнее. Тест `test_no_api_keys_in_repository` следит, чтобы ключи не попали в код.

Обычные правки, PR, ручная проверка, понижение версии, перезапись истории и существующий или более новый тег выпуск не запускают. Уже опубликованный выпуск не перезаписывается, сборки одной версии выполняются последовательно.

Ручной запуск оставлен для сборки артефакта (без «version») или повторной попытки после сбоя: workflow «Сборка для Windows» с полем «version» (Actions → Run workflow, или `gh api -X POST repos/r4v3r-63/copy-video-finder/actions/workflows/build.yml/dispatches -f ref=main -f inputs[version]=X.Y.Z`). Для сборки исходного проверенного коммита после сбоя перезапустить неуспешные задания исходного CI: ручной запуск с `ref=main` собирает текущий `main`. Workflow сам создаст тег vX.Y.Z и выпуск в Releases после успешной сборки. Тег `v*`, отправленный вручную, работает так же; из облачного сеанса Claude отправка тегов запрещена. Старые выпуски удаляет workflow «Удаление старых выпусков» (`cleanup-releases.yml`, только вручную): оставляет `keep` последних, по умолчанию `dry_run=true` — только список; удаляет с `dry_run=false` (из облачного сеанса выпуски напрямую удалять нельзя).

## Git и GitHub

- Новый отдельный репозиторий на GitHub, рабочее название `copy-video-finder` (не репозиторий ARC Raiders).
- На первом этапе: `git init`, создать репозиторий на GitHub под аккаунтом пользователя (`gh repo create`), первый пуш.
- Коммит после каждого значимого шага, понятные сообщения на русском; пуш на GitHub.
- В `.gitignore`: папка «Данные», ключи API, кэш, скачанные ролики, `.venv/`, `build/`, `dist/`, `__pycache__/`.

## Сборка и поставка

- Автообновление: при запуске программа смотрит `releases/latest` (репозиторий публичный, ключ не нужен) и предлагает обновиться. ZIP скачивается в «Данные/update», сверяется с `.sha256` из выпуска, распаковывается; `update.cmd` ждёт выхода программы, копирует файлы `robocopy /E` (без удаления) и запускает её снова. «Данные» не трогаются. Поэтому имя ассета `CopyVideoFinder-vX.Y.Z-windows.zip` и файл `.sha256` рядом менять нельзя.

- Только PyInstaller onedir. Однофайловый exe не делать: Касперский принимает его за троян.
- FFmpeg и все зависимости — внутри папки сборки.
- GitHub Actions на windows-latest собирает ZIP и публикует его в Releases.

## Как работать

- Ревью 20.10.2026 для 0.24.0: `docs/CODE_REVIEW.md`. Сохранение пользовательских JSON — через `paths.atomic_write_text`; настройки защищены от одновременной записи. Изменившаяся лицензия при обновлении сведений сбрасывает её подтверждение, остальные пользовательские поля не меняются; скачивание повторно не подтверждает лицензию. Общий доступ к актуальным одноразовым ключам VK — `token_supplier` и блокировка приложения/устройства. Установка обновления требует HTTPS и SHA-256. Имена архивов выпуска сохранены.
- Разработка идёт по этапам из раздела 11 ТЗ. Каждый этап заканчивается программой, которая запускается и проверяется.
- Новая логика лицензий, дублей и статистики сопровождается тестами на фикстурах из tests/fixtures, без обращений к сети.
- Фоновые потоки при закрытии окна отменяются и дожидаются полностью (`closeEvent`, `FramesStrip.stop`, `UpdateController.stop`): поток, переживший окно-родитель, роняет программу. Долгие внешние процессы (FFmpeg) — через Popen с опросом отмены.
- Тесты окон: одно `QApplication` на весь прогон создаёт `tests/conftest.py` (режим offscreen); своё приложение Qt в тестах не создавать.
- Интерфейс и сообщения пользователю — на русском языке.
