# Архитектура Copy Video Finder

Программа организована по ответственности модулей. Направления импортов, отсутствие циклов,
изоляцию Qt и ядра проверяет `tests/test_architecture.py` в локальных тестах и CI.
Решение и причины — [ADR-0001](decisions/0001-project-structure.md).

В корне `app/` допустимы только `__init__.py`, `paths.py` и `main.py`.
Новый пакет добавляется с назначением, правилами зависимостей и проверкой этих правил.
`__init__.py` не должен запускать приложение, фоновые операции или сетевые запросы при импорте.

## Направление зависимостей

Строки ниже идут от верхнего слоя к нижнему. Модуль может импортировать свой слой
и любой нижний, но не верхний. Циклы запрещены также внутри одного слоя.

| Пакет | Ответственность | Что сюда не относится |
| --- | --- | --- |
| `main.py` | Сборка приложения, выбор режима запуска | Правила поиска, фильтров и лицензий |
| `diagnostics/` | Сквозные проверки с локальным HTTP-сервером, Qt и настоящими файлами | Функции, необходимые обычному рабочему сценарию |
| `ui/` | Отображение, действия пользователя, подключение сигналов | Сетевая загрузка и длительные операции в потоке окна |
| `workers/` | Запуск сервисов в QThread, сигналы, отмена и ожидание | Повторная реализация сценариев |
| `export/` | Формирование экспортируемых файлов | Управление окнами и собственная загрузка видео |
| `services/` | Сценарии и координация загрузок/поиска | Qt-виджеты и зависимости от интерфейса |
| `sources/` | API и разрешённые механизмы источников, разбор ответов, лимиты | Пользовательский каталог и подтверждение лицензий |
| `storage/` | Сохранение и миграции данных | Вызовы источников и управление интерфейсом |
| `core/` | Модели, лицензии, релевантность, ориентация, фильтры, правила URL | HTTP, SQLite, подпроцессы и Qt |
| `__init__.py`, `paths.py` | Версия и общие пути портативной программы | Импорты из верхних слоёв |

`core/processes.py` и `core/query.py` пока совмещают модели со чтением справочника/словаря JSON
через `paths.py`. Это существующая ограниченная ответственность; новые сценарии хранения
и миграции относятся к `storage/`. SQLite-кэш `sources/cache.py` обслуживает только запросы
источников и пока остаётся рядом с HTTP-слоем.

Qt разрешён в `ui/`, `workers/`, `main.py` и `diagnostics/`.
Единственное исключение в экспорте — `export/report.py`, где PDF создаётся средствами Qt.
Синхронные сервисы сообщают о ходе работы обратными вызовами, отмена — через `threading.Event`.
Ограниченная параллельность сервисов допустима, если сервис дожидается своих потоков перед возвратом.

## Куда добавлять изменения

- **Новый источник:** адаптер в `sources/`, подключение в `sources/registry.py`, сохранённый ответ
  в `tests/fixtures/`, тест разбора и ограничений в `tests/sources/`. Прямые адреса файлов — только из ответа источника.
- **Новый фильтр или правило:** функция/модель в `core/`, тест в `tests/core/`.
  Сценарий применяет правило до формирования очереди, интерфейс задаёт параметры.
- **Новый сценарий:** синхронная функция или класс в `services/`; при длительной работе —
  тонкая обёртка в `workers/`, управление и результат — в `ui/`.
- **Новый вид данных:** чтение, запись и миграции в `storage/`; тесты в `tests/storage/`
  проверяют совместимость старых данных и сохранение пользовательских отметок.
- **Новая команда меню:** обработчик в `ui/actions/`; главное окно только подключает команду.
- **Новый элемент интерфейса:** переиспользуемый компонент в `ui/widgets/`, самостоятельное
  окно в `ui/dialogs/`, раздел в `ui/tabs/`. Цвета, размеры и шрифты — только в `core/design.py`.
- **Проверка поставки:** сценарий в `diagnostics/`, команда-обёртка в `scripts/`,
  явный аргумент запуска в `main.py`. Рабочие слои не импортируют диагностику.

Имена файлов отражают ответственность: `stock_listing.py`, `stock_download.py`, `download_files.py`.
Крупный модуль делится по самостоятельным задачам, когда для этого есть реальная причина.
Общие функции помещаются в пакет их ответственности; отдельный универсальный `utils.py` не создаётся.
Существующие модули не дублируются ради новой вкладки или площадки.

## Связь интерфейса и фоновой работы

`ui/context.AppContext` содержит зависимости и общее состояние окна. Вкладки сообщают
о событиях сигналами `message` и `catalog_changed`; они не управляют соседними вкладками напрямую.
`MainWindow` собирает части. При закрытии каждая часть отменяет фоновые операции и дожидается
их завершения; только после этого закрываются каталог и кэш.

Веб-плеер `ui/widgets/site_player.py` выбирает платформенный адаптер:
`windows_site_view.py` (WebView2/WinForms) или `qt_site_view.py` (Linux Qt WebEngine).
Общие правила адресов находятся в `core/web_urls.py`; платформенные адаптеры не импортируют
собирающий их `SitePlayer`. В Windows отдельный STA-поток отвечает только за браузер,
получает команду завершения и закрывается через `Join()`. JS-моста к Python нет.

## Код, ресурсы и пользовательские данные

`resources/` содержит встроенные файлы поставки. Изменяемые настройки, каталог, кэш и журналы
находятся в `Данные` рядом с EXE, при разработке — в `app/Данные`, пути задаёт `paths.py`.
Код не зависит от текущего рабочего каталога. В репозиторий и ZIP выпуска пользовательские данные не входят.

- `Данные/settings.json` — пользовательские настройки и API-ключи.
- `Данные/download-info` — лицензии TXT и метаданные JSON скачанных файлов.
- `Данные/download-jobs` — временные задания, незавершённые и повреждённые файлы.
- `Данные/update` — распакованное обновление и установщик; состояние и журнал — рядом в `Данные`.
- Выбранная пользователем папка видео — только готовые MP4; она может находиться вне `Данные`.

Имена выпуска `CopyVideoFinder-vX.Y.Z-windows.zip` и `.sha256`, расположение `Данные`
и форматы сохранённых данных являются контрактами совместимости.

## Проверки структуры и поставки

`tests/test_architecture.py` анализирует также относительные импорты, `from package import module`
и импорты внутри функций. Он проверяет расположение модулей, направление зависимостей,
изоляцию ядра/Qt и отсутствие циклов. Проверки самого анализатора защищают эти правила от регрессий.

Модульные тесты располагаются в папках соответствующего слоя; `tests/regression/` содержит
межслойные сценарии, `tests/release/` — выпуск, `tests/fixtures/` — ответы API и локальные медиафайлы.
Исторические межслойные тесты остаются на своих местах до отдельного обоснованного переноса.

Сквозные сценарии `diagnostics/site_player.py`, `site_download.py`, `stock_link.py` и `updater.py`
входят в сборку, потому что проверяют настоящий EXE. Внешние команды
`scripts/check_*.py` и аргументы `--check-*` сохраняются. PyInstaller обнаруживает диагностические
модули через явные импорты `main.py`; фикстуры передаются проверке извне и в поставку не добавляются.

Перед коммитом: `ruff check app tests scripts` и `QT_QPA_PLATFORM=offscreen pytest -q`.
После переноса модулей дополнительно проверяются локальные сквозные сценарии,
Windows-сборка и проверки собранного EXE в GitHub Actions.
