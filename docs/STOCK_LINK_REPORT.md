## Реализовано

- Четвёртый раздел «Загрузка по ссылке»; прежние три раздела сохранены.
- Разбор URL Pixabay и Internet Archive, определение источника, адаптеры официальных API, кэш и общие лимиты.
- Пагинация до доступной границы источника, исключение дублей, отдельные числа общего/доступного/полученного количества, подходящих, выбранных, скачанных и ошибок.
- Локальные фильтры секунд с независимыми необязательными границами и включением 10/30; неизвестная длительность при активном фильтре исключается. Некорректные, отрицательные, бесконечные значения и обратный диапазон отклоняются.
- Горизонтальная, вертикальная или любая ориентация по размерам; выбор максимального/1080p/720p с ближайшим доступным вариантом и уведомлением.
- Табличная модель без виджетов на каждую строку, асинхронные превью с ограничением параллельности, обе темы, оригинальная страница и варианты качества/размеров.
- В 0.26.0–0.26.1 у Pixabay был индивидуальный выбор. По новому решению пользователя в 0.26.2 пакетные действия доступны и для Pixabay: число видео за запуск либо все подходящие на выбранной странице API. Лимиты источников не изменены.
- Общие `fetch` и `run_job`: исходные байты без перекодирования, .part и безопасное переименование, докачка Range/If-Range, отмена, повторы временных сетевых ошибок и соблюдение Retry-After.
- Пауза и продолжение; ошибки отдельного файла не останавливают очередь. Выход отменяет операции и дожидается потоков/дочерних процессов.
- TXT лицензии и JSON метаданных: ID, источник, оригинал, дата, длительность, размеры, размер файла, путь, SHA-256, лицензия и `license_confirmed=false`. Скачивания не добавляются в каталог услуг автоматически.
- Повторный файл с совпадающим ID, размером и SHA-256 используется без скачивания. Неполные/нечитаемые файлы откладываются с `.invalid`; Windows-поставка содержит ffprobe.
- Ключ Pixabay берётся из существующих настроек/секретов; в репозиторий и журнал не добавлен.

## Исправления после ревью — 0.26.1

- Сетевая ошибка выдачи больше не выводит исходный текст requests с возможным ключом в URL. Регрессия проверяет сообщение с синтетическим приватным значением.
- Кнопка отмены только выставляет флаги; ожидание потоков выполняется при закрытии. Новая операция начинается после фактического завершения старой, результаты старого потока не попадают в новую выдачу.
- К имени отдельного скачивания добавлен устойчивый суффикс SHA-256 от пары источник/ID: обрезанные длинные ID не совпадают. Проверенные JSON-файлы 0.26.0 распознаются для совместимости.

## Ограничения и отличия от сайта

1. `time_lapse=true` отсутствует среди поддерживаемых параметров Video API. Тип API `film/animation` и текстовые теги не подтверждают таймлапс. Параметр не отправляется в API, обычные кандидаты не помечаются таймлапсами, предупреждение остаётся над списком. Ключевой запрос `time lapse` можно задать в самом URL, но это также не подтверждение типа съёмки.
2. API не воспроизводит фильтр ориентации сайта: программа проверяет разрешение локально. Неизвестные размеры исключаются при конкретной ориентации. Чёрные поля и ориентация самого содержимого в этом отдельном режиме не анализируются; правила основного каталога не изменены.
3. Документированная выдача Pixabay ограничена 500 результатами одного запроса и размером страницы до 200. Программа не обходит это ограничение и не дробит запрос для обхода. При отказе источника по лимиту уже полученные результаты остаются в списке; повторный запуск использует кэш предыдущих страниц. Указанная в URL страница относится к API-пагинации; разбиение страниц сайта может отличаться.
4. Для Internet Archive метаданные длительности/размеров могут отсутствовать. При активном фильтре неизвестные значения исключаются. Закрытые/удалённые файлы и ролики с ограничениями могут быть недоступны загрузчику. Элементы Archive с несколькими отдельными видео могут определяться как плейлист и не скачиваются загрузчиком одиночного ролика.
5. Поддержаны только эти два адаптера. Для других сайтов сообщается об отсутствии поддержки; закрытые API, CAPTCHA, вход и блокировки не обходятся.
6. Пауза прямого файла работает между блоками. Для отдельного загрузчика страницы приостанавливается очередь после текущего ролика; загрузка этого ролика не замораживается.
7. Докачка зависит от Range/If-Range и валидаторов источника; при смене версии/URL начинается заново. Позиция очереди после аварийного завершения не восстанавливается автоматически: результаты можно получить повторно, завершённые файлы распознаются по метаданным.
8. Лицензия из метаданных сохраняется, но разрешение коммерческого публичного показа не подтверждается автоматически. Видео не включается в каталог и покрытие услуг.
9. Проверки API выполнялись на сохранённых фикстурах и loopback. Настоящий запрос Pixabay с пользовательским ключом не выполнялся. Страница официальной документации в этой среде ответила HTTP 403; защита не обходилась. Опора реализации — публичный контракт Video API и существующий адаптер; поведение живого сервиса может отличаться.

Официальные ссылки: [Pixabay Video API](https://pixabay.com/api/docs/#api_search_videos), [условия Pixabay API](https://pixabay.com/api/docs/), [Internet Archive Advanced Search](https://archive.org/advancedsearch.php), [руководство загрузок Internet Archive](https://help.archive.org/help/downloading-a-basic-guide/), [официальная CLI-документация пакетных загрузок Archive](https://archive.org/developers/internetarchive/cli.html#download).

## Дополнение 0.26.2

Добавлены явный выбор страницы API и объёма запуска. Числовой предел применяется после фильтрации к уникальным незавершённым роликам, включая ручной выбор. «Все на странице» ограничено конкретной страницей, весь набор страниц не включается автоматически. Программная блокировка пакетного выбора Pixabay снята по прямому указанию пользователя; условия и реальные ограничения API остаются ответственностью использования, разрешение площадки не предполагается автоматически.
